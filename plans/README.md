## Findings considered and rejected (so nobody re-audits them)

- **Kafka offset-commit message loss** (subagent claim: `track_received` before
  validation loses messages): rejected — DLQ publish (`kafka/consumer.rs:1049`)
  happens before the offset is committed (`:1062`); not lost.
- **Redis unbounded concurrency** (permit dropped before spawn): rejected —
  `acquire_owned()` (`redis/consumer.rs:1012`) returns an owned permit moved into
  the `async move` task and dropped at `:1114` after routing. Correctly bounded.
- **Kafka Retry/Defer republish race**: rejected — `completion` is threaded into
  `run_delayed_republish` and signaled after the publish lands (the `f3c843f`
  fix). Working as intended.
- **Backoff jitter overflow** (`retry.rs:61`): rejected — `min = 0.5·base ≥ 0`,
  so `nanos` is always positive and bounded (~45e9 ns); the cast can't overflow
  or go negative.
- **Commit despite DLQ-publish failure** (`kafka/consumer.rs:398-410`): rejected
  — documented by-design (prevents a poison-pill infinite loop; metric + trace
  surface it to operators).
- **RabbitMQ poisoned-key pending drain**: rejected — by-design (timeout
  eviction); not worth a plan.
- **PERF "profile first" items** (per-message allocations, hashmap lookups,
  autoscaler mutex-across-await, publisher pool vs. single-conn): rejected as
  findings — no concrete evidence, only "go profile X." The hot paths already
  carry perf-fix annotations (perf-K-5/9, hoisted connections); revisit only with
  a flamegraph showing a real bottleneck.
- **"Delivery semantics only happy-path tested"** (original TEST-01 framing):
  rejected as framed — every backend already has thorough retry/DLQ/defer/reject/
  sequenced/timeout integration tests (and Redis has crash-recovery tests). The
  real residual (fast Docker-free unit coverage of the decision table) is folded
  into plan 004.
- **Header-constant duplication across backends**: noted but not planned — the
  constant *values* legitimately differ per transport (AMQP/Redis use
  `x-*-count`; Kafka/NATS use `Shove-*`), so a blind unification would change
  wire behavior. Low value relative to risk.
