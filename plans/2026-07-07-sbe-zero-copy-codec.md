# SBE codec support (zero-copy)

## Goal

Add Simple Binary Encoding (SBE) codec support to `shove`, preserving SBE's
zero-copy flyweight model end-to-end: publish passes the user-encoded frame
through without re-encoding, and the handler reads fields directly from the
received buffer via the user's generated flyweight decoder.

## Background

- SBE schemas are compiled by `real-logic/simple-binary-encoding`'s `sbe-tool`,
  whose Rust generator emits dependency-free flyweight encoders/decoders
  (`WriteBuf`/`ReadBuf`, `XxxEncoder`/`XxxDecoder`) plus per-message constants
  (`SBE_SCHEMA_ID`, `SBE_TEMPLATE_ID`, `SBE_SCHEMA_VERSION`, `SBE_BLOCK_LENGTH`).
- The wire frame starts with the standard 8-byte SBE message header composite:
  `blockLength:u16, templateId:u16, schemaId:u16, version:u16`, byte order per
  schema `byteOrder` (default littleEndian).
- Because generated codecs are flyweights over `&[u8]`/`&mut [u8]`, an owned
  "decoded struct" does not exist. The shove-side message type must therefore
  be an owned, validated *frame* (bytes), not a materialized struct.

## Design

### 1. `bytes` promoted to a required dependency

`bytes::Bytes` becomes part of the core `Codec` trait surface. `bytes` is
already in the dependency tree unconditionally (via `tokio-util`), and was
already a direct optional dep for the `kafka` feature. Move it to required,
drop `dep:bytes` from the `kafka` feature list.

### 2. `Codec` trait extension (backward compatible)

New defaulted methods on `Codec<M>` in `src/codec.rs`:

```rust
fn encode_bytes(value: &M) -> Result<Bytes> {
    Self::encode(value).map(Bytes::from)
}
fn decode_owned(bytes: Bytes) -> Result<M> {
    Self::decode(&bytes)
}
```

Existing codecs (JSON, raw, protobuf, custom downstream) compile unchanged and
get correct behavior: `Vec<u8> -> Bytes` is zero-copy, and decode borrows.

### 3. `sbe` cargo feature + `src/codecs/sbe.rs`

Feature `sbe = []` — zero new dependencies. Module contents:

- `SbeMessage` marker trait (implemented per topic message type, typically a
  unit struct type-tag alongside the generated codec module):
  - `const SCHEMA_ID: u16`
  - `const TEMPLATE_ID: u16`
  - `const SCHEMA_VERSION: u16`
  - `const BLOCK_LENGTH: u16`
  - `const BYTE_ORDER: SbeByteOrder = SbeByteOrder::LittleEndian`
- `SbeByteOrder { LittleEndian, BigEndian }` — must match the schema's
  `byteOrder`.
- `SbeHeader { block_length, template_id, schema_id, version }` with
  `ENCODED_LENGTH = 8`, read/write honoring byte order. No-panic parsing.
- `SbeFrame<T: SbeMessage>` — the topic `Message` type. Owns `Bytes` holding
  the complete wire frame (header + body). Constructor
  `SbeFrame::new(impl Into<Bytes>)` validates:
  - length >= 8
  - `schema_id == T::SCHEMA_ID` (else `SchemaIdMismatch`)
  - `template_id == T::TEMPLATE_ID` (else `TemplateIdMismatch`)
  - wire `version`/`block_length` are NOT rejected — SBE extension semantics:
    the acting values are exposed via `header()` and the flyweight decoder
    handles older/newer versions.
  Accessors: `header()`, `as_bytes()` (full frame), `body()` (after header),
  `into_bytes()`, `AsRef<[u8]>`, cheap `Clone`, `Debug`, `PartialEq`.
- `SbeCodecError` (thiserror): `TooShort`, `SchemaIdMismatch`,
  `TemplateIdMismatch`.
- `SbeCodec` with `impl<T: SbeMessage> Codec<SbeFrame<T>> for SbeCodec`:
  - `NAME = "sbe"`
  - `encode` -> `frame.as_bytes().to_vec()` (fallback path)
  - `encode_bytes` -> `Bytes` refcount clone (zero-copy)
  - `decode` -> `Bytes::copy_from_slice` + validate (single memcpy fallback)
  - `decode_owned` -> validate + wrap (zero-copy)
  - `encode_to_string` inherits the default and fails on non-UTF-8 output at
    publish time — the correct failure mode for SNS/SQS and Redis Streams,
    same as protobuf.

Usage shape (user side):

```rust
// generated by sbe-tool: order_codec.rs with OrderEncoder/OrderDecoder
struct Order;                     // type tag
impl SbeMessage for Order { ... consts from generated module ... }

define_topic!(OrdersTopic, SbeFrame<Order>, ORDERS_TOPOLOGY, codec = SbeCodec);

// publish: encode once with the generated flyweight, then wrap
let frame = SbeFrame::<Order>::new(buf)?;   // validates header
publisher.publish::<OrdersTopic>(&frame).await?;

// consume: handler receives SbeFrame<Order>, wraps generated decoder over
// frame.as_bytes() — no copies, no materialization
```

### 4. Backend zero-copy plumbing

Switch owned-buffer paths to the new methods; leave borrowed paths on
`decode` (where the SBE fallback costs exactly one memcpy, the minimum):

| Backend | Publish | Consume |
|---|---|---|
| NATS | `encode_bytes` -> async-nats `Bytes` payload (zero-copy) | `decode_owned(msg.payload.clone())` — `Bytes` refcount (zero-copy); applies to main, sequenced, and DLQ paths |
| Kafka | `encode_bytes`, pass `&bytes` to rdkafka (rdkafka copies internally regardless; avoids the extra frame->Vec copy) | keep `decode(payload_slice)` — buffer is borrowed from librdkafka; one memcpy unavoidable |
| RabbitMQ | `encode_bytes`, pass `&bytes` to `publish_raw` | keep `decode(&delivery.data)` — `delivery.data` is republished on retry/hold/DLQ routes, cannot be moved out |
| InMemory | `encode_bytes`; `Envelope.payload` becomes `Bytes` (private struct) | `decode_owned(env.payload.clone())` (zero-copy) |
| SNS/SQS, Redis | string-based wire (`encode_to_string`); binary SBE correctly fails at publish time | unchanged |

### 5. Exports, docs

- `src/codecs/mod.rs`: `#[cfg(feature = "sbe")] pub mod sbe;`
- `src/lib.rs`: re-export `SbeCodec`, `SbeFrame`, `SbeMessage`, `SbeHeader`,
  `SbeByteOrder`, `SbeCodecError` under the feature, with docsrs cfg.
- Cargo.toml feature comment; docs/pages/concepts/codecs.mdx new SBE section
  mirroring the protobuf section.

## Tests (TDD)

1. Unit (in `src/codec.rs`): `encode_bytes`/`decode_owned` defaults round-trip
   for JSON; `Bytes::from(vec)` path.
2. Unit (in `src/codecs/sbe.rs`), written first:
   - header round-trip little- and big-endian
   - frame validation: too-short, schema mismatch, template mismatch
   - round trip through `SbeCodec` with a hand-rolled flyweight message
     mimicking sbe-tool output
   - `encode_bytes` and `decode_owned` are zero-copy (pointer equality on the
     underlying buffer)
   - version/block-length passthrough (acting values readable from `header()`)
   - `NAME == "sbe"`; decode errors surface as `ShoveError::Codec { codec: "sbe" }`
   - `encode_to_string` on a non-UTF-8 frame fails with the codec error
3. Integration `tests/sbe_codec_inmemory.rs` (features `sbe,inmemory`):
   publish/consume round trip of an `SbeFrame` topic through the in-memory
   broker; handler decodes fields via the hand-rolled flyweight.
4. Existing suites stay green: `cargo nextest run --no-default-features`,
   clippy all-features/no-default-features, fmt.
