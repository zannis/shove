## What this changes

The README's four throughput bullets and the docs performance table are
hand-copied out of a stress run. They carry no date and no version, nothing
regenerates them, and both claim hardware and a shove release that are no
longer current. A reader cannot tell a fresh number from a stale one.

This adds the generator that removes the hand-copying step, plus the first real
results document for it to read.

- **`examples/chartgen.rs`** — a thin CLI: `chartgen --input <results.json> --out-dir <dir>`.
- **`examples/common/chartgen.rs`** — the generator: schema model, the
  enforcement rules, and the five chart families.
- **`tests/chartgen.rs`** — 17 tests. The generator lives under `examples/` and
  Cargo defaults `[[example]]` targets to `test = false`, so this target is what
  actually makes them run (the same `#[path]` idiom `tests/bench_harness.rs`
  uses).
- **`benches/results/bench-results.json`** — the first real results document.
- **`docs/public/bench/*.svg`** — the five committed charts.

The example carries **no `required-features`** on purpose: the chart-staleness
CI leg only reads a JSON file and writes SVGs, and a backend feature here would
drag `librdkafka-dev`/`libsasl2-dev` and a full broker build into that job.

## The five schema rules are assertions, with a test each

| Rule | Behaviour | Test |
|---|---|---|
| Unknown `schema_version` | hard error, at `validate` **and** at every render entry point | `unknown_schema_version_is_rejected`, `unknown_schema_version_blocks_every_chart` |
| `representative: false` | never plots an absolute magnitude — normalised to its own peak, drawn "shape only", and excluded from the axis range | `non_representative_backend_never_plots_an_absolute_value`, `a_non_representative_run_does_not_stretch_the_axis` |
| `unsupported[]` | explicit `n/s` marker plus the reason in the caption; never a zero, never a silent gap | `unsupported_flow_is_marked_not_zeroed_and_not_dropped`, `a_backend_absent_from_a_slice_is_named_rather_than_omitted` |
| Provenance | `generated_at` + shove version + rust version + hardware in every caption | `every_chart_renders_the_provenance_block` |
| Empty `results[]` | hard error unless every flow is declared unsupported | `silently_empty_run_is_rejected`, `empty_run_is_allowed_when_every_flow_is_declared_unsupported` |

Two things worth calling out in how these are enforced:

**The non-representative rule is structural, not a label.** The axis range is
computed only from representative series, so a LocalStack run cannot stretch the
scale the published numbers are read against. The test adds a 5M msg/s
non-representative series and asserts the representative axis does not move.

**Unknown flows are deliberately *not* rejected.** The schema bumps
`schema_version` only on removal or semantic change, so a future additive flow
must keep rendering rather than hard-fail. `KNOWN_FLOWS` is used only to decide
whether an empty run declared itself.

## Byte-deterministic output

The staleness leg diffs regenerated SVGs against the committed ones, so
identical input must produce identical bytes on any host:

- no wall clock — every rendered timestamp comes from the document
- ordered collections throughout, never `HashMap`
- `plotters` pinned to `default-features = false, features = ["svg_backend", "line_series"]`

That last one is load-bearing rather than tidy. The default set enables `ttf`,
which resolves text extents through system fonts; those differ between a laptop
and `ubuntu-latest`, so every label coordinate — and therefore every byte —
would move on a run that changed nothing, and the leg would be permanently red.
`Cargo.lock` confirms no `font-kit`/`ab_glyph`/`ttf-parser`/`rusttype` anywhere
in the tree.

Verified identical across separate processes **and** across debug and release
builds, not just twice in one process.

## Theme neutrality

One file per family, no `-dark` siblings. crates.io renders the README on a
light background with no theme-switching mechanism, so a single
both-background-legible SVG has to exist regardless; a `-dark` variant would be
a file the README could never use and a second surface the staleness leg would
have to keep in sync.

Enforced by test: the background is never painted, no fill is white or
near-black, and nothing external is referenced (no webfont, stylesheet, raster
or script), which matters because `raw.githubusercontent.com` serves SVGs under
`default-src 'none'` and a dropped resource just makes labels vanish.

Text sits at or above the 3:1 WCAG large-text threshold against both a light and
a dark page. Note that plotters emits roughly `0.806 x` the declared size, so
the constants are ~1.24x the intended pixel size — an earlier version rendered
14px text at 11.3px and an unstyled axis label in pure black.

## The committed results document

Produced by the Tier B harness on this host. Coverage:

| backend | scenarios | consumer counts | payloads |
|---|---|---|---|
| `inmemory` | 84 | 1, 2, 4, 8 | 64 B / 1 KiB / 64 KiB |
| `kafka` (3.9, KRaft) | 24 | 1 | 64 B / 1 KiB / 64 KiB |
| `nats` (2.10 JetStream) | 21 | 1 | 64 B / 1 KiB / 64 KiB |

129 rows, 0 failures, and one real `unsupported[]` entry (`consume_batch` on
NATS — `run_batch` is Kafka-only).

**Two honest limitations, both visible in the charts rather than hidden:**

1. Kafka and NATS were measured at a single consumer count, so they render as
   labelled single points on the consumer-count chart rather than as a fake
   line. Extending that needs the stress examples to accept a broker URL from
   the environment — today they hardwire testcontainers — which is the producer
   side and out of scope here.
2. These numbers come from a shared 6-core aarch64 container, not the M4 Max
   the published numbers are meant to come from. The provenance block says so on
   every chart, which is exactly the mechanism this epic adds. Refreshing from
   real benchmarking hardware is a re-run of the generator against a new
   document, with no code change.

RabbitMQ, Redis and SQS carry no rows yet. SQS in particular is what the
`representative: false` path exists for, so that path is covered by tests rather
than by data.

## Framework overhead comes from the in-process backend

The ticket sources this family from "Tier A". Tier A is criterion, whose output
is uncommitted `target/criterion` estimates — the staleness leg regenerates from
the *committed JSON* with no broker, so it cannot read them, and the schema has
no Tier A block to put them in.

The in-process backend measures the same thing: shove's own per-message cost
with the broker removed. `ns/msg = 1e9 / throughput_msg_per_sec` over the
`inmemory` run needs no schema change, no second CLI argument, and no new
producer. A document without an in-process run fails loudly rather than
substituting whichever backend happens to be present.

## Verification

- `cargo nextest run --no-default-features` — **205 passed, 0 failed**
- `cargo test --no-default-features --doc` — 3 passed (nextest skips doctests)
- `cargo fmt -- --check` — clean
- `cargo clippy --no-default-features --all-targets -- -D warnings` — clean
- `cargo clippy --lib --no-default-features --features {inmemory,redis-streams,nats}` — clean
- Determinism: byte-identical across separate processes and across debug/release
- Layout: every `<text>` verified inside the 960x560 canvas against the real
  document and against a deliberately long `unsupported[]` reason

`cargo clippy --all-features` cannot run in this environment — `kafka-ssl` pulls
`openssl-sys`, and there is no `pkg-config` or system OpenSSL. Rather than leave
that gate as an untested claim, its two legs are bounded:

- **`check` (`--all-features --all-targets`)** — approximated with every feature
  the environment can build, which is all of them except the two openssl-bound
  ones: `rabbitmq,rabbitmq-transactional,aws-sns-sqs,pub-aws-sns,nats,kafka,`
  `kafka-schema-registry,redis-streams,inmemory,metrics,audit,protobuf,`
  `env-config,sbe,test-support` — plus `--all-targets`. Clean. The residue is
  derived from `[features]` rather than remembered, and is exactly `kafka-ssl`
  and `kafka-msk-iam`. Neither can change how this diff lints: the three new
  files contain no `#[cfg(...)]` and no `feature = ` predicate, so they compile
  identically under any feature set.
- **`feature-lint` (`--lib --no-default-features --features <set>`)** — `--lib`
  scoped, so it never compiles `examples/`, `tests/` or `benches/`, which is
  where this entire diff lives. `src/` is untouched and the subtree hash proves
  it: `git rev-parse origin/main^{tree}:src` and `HEAD^{tree}:src` are both
  `162858e5`. The gate lints byte-identical code at this head and at a base CI
  already proved green. The `Cargo.toml` change is a `[dev-dependencies]` entry
  and an `[[example]]` target declaration; neither is built under `--lib`.
